# Suggested repository labels

Apply labels to real work; no issues are created automatically.

| Label | Purpose |
| --- | --- |
| good first issue | Small, well-scoped work with reproduction and acceptance criteria |
| help wanted | Maintainer-reviewed work ready for a contributor |
| bug | Incorrect behavior with a reproduction |
| enhancement | New or improved capability |
| documentation | Guides, CLI help or explanations |
| scanner | Inventory, stack detection or readiness checks |
| integration | Reports, provider contracts or future opt-in diagnostics |
| testing | Fixtures, coverage or CI |
| security | Defensive hardening; disclose vulnerabilities privately first |

Do not label speculative proposals good first issue until the scope and prerequisites
are clear. Use Discussions for open-ended design when enabled. Releases should follow
validated milestones and changelog review, not contribution or badge targets.
